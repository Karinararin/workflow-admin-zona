SHEET 01 / 09

Masalah & Tujuan

REF — LATAR BELAKANG SISTEM

✕ Kondisi Sekarang

  • Tiap admin (Taruna, SMA, Sekdin, dst) punya sheet sendiri-sendiri.
  • Tidak ada yang bisa lihat gambaran keseluruhan dalam satu tempat.
  • Tutor yang sama bisa dipakai dua admin di jam yang sama tanpa saling tahu.
  • Fee tutor dihitung manual per sheet, rawan salah dan lupa update.
  • Rekap jumlah siswa, pendapatan, dan status kelulusan harus digabung manual.

✓ Tujuan Sistem Baru

  • Satu sistem, satu database — semua admin input di tempat yang sama.
  • Setiap admin punya kode warna sendiri, terlihat siapa mengelola data apa.
  • Sistem otomatis menolak booking tutor jika sudah dipakai admin lain di jam sama.
  • Fee tutor terhitung otomatis: rate per pertemuan × jumlah sesi terlaksana.
  • Dashboard menampilkan jumlah siswa, pendapatan, fee keluar, dan status kelulusan.
SHEET 02 / 09

Struktur Role & Kode Warna Admin

REF — AKSES PENGGUNA

Setiap zona/program punya admin sendiri dengan warna identitas. Super Admin (pemilik bimbel) melihat semua data tergabung, lengkap dengan label warna asal admin — sehingga sekilas langsung tahu data itu milik siapa.

RoleWarnaMenanganiAkses Data
Super Admin Putih / Netral Pemilik / pengawas seluruh operasional Lihat & edit semua zona, semua laporan keuangan & fee
Admin A Biru Program Taruna Hanya data zona Taruna (siswa, jadwal, tutor, fee miliknya)
Admin B Hijau Program SMA Hanya data zona SMA
Admin C Ungu Program Sekdin Hanya data zona Sekdin
Admin baru... Warna baru bisa ditambah Zona/program baru Menyusul sesuai kebutuhan

Catatan: tutor bersifat lintas-zona — tutor X bisa dipakai Admin A dan Admin B, tapi tidak boleh di jam yang sama (lihat Sheet 04).

Tabel JADWAL/SESI adalah pusat sistem — setiap booking tutor dicatat di sini, lintas semua admin, sehingga bisa dicek bentrok jadwal secara real-time.

SLOT TERPAKAI
Admin B tidak bisa menyimpan jadwal ini. Sistem menampilkan: "Tutor RIZKY sudah dibooking Admin A pada 06 Agu 2026, 15:30" — Admin B otomatis diarahkan memilih jam lain atau tutor lain.

Aturan Validasi

  • Kunci unik = kombinasi tutor_id + tanggal + jam, berlaku lintas semua admin/zona.
  • Jika sesi diubah statusnya jadi reschedule atau dibatalkan, slot otomatis terbuka kembali untuk admin lain.
  • Super Admin dapat melihat kalender gabungan seluruh tutor untuk memantau slot kosong.
SHEET 05 / 09

Kalkulasi Fee Tutor Otomatis

REF — LOGIKA KEUANGAN

Rate per pertemuan diset manual oleh admin per tutor (karena tiap tutor beda tarif). Sistem hanya mengalikan otomatis dengan jumlah sesi yang statusnya Terlaksana pada periode yang dipilih.

FEE TUTOR  =  RATE PER PERTEMUAN  ×  JUMLAH SESI TERLAKSANA RATE diset admin saat menambahkan tutor ke zona-nya · SESI dihitung otomatis dari tabel JADWAL berstatus "Terlaksana"
Tutor: RIZKY — Zona Taruna
Rate / pertemuanRp 100.000
Sesi terlaksana (Agu 2026)5×
Total FeeRp 500.000
Tutor: AEZAL — Zona SMA
Rate / pertemuanRp 75.000
Sesi terlaksana (Agu 2026)8×
Total FeeRp 600.000

Sesi berstatus "Belum Belajar" atau "Reschedule" tidak dihitung sampai statusnya berubah menjadi "Terlaksana". Rate bisa berbeda untuk tutor yang sama di zona berbeda, karena disimpan per kombinasi tutor + zona (lihat tabel TUTOR_RATE di Sheet 03).
